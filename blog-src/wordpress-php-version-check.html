「うちのホームページは WordPress で作っているけれど、今回の PHP の脆弱性は関係あるの？」という質問を、よく目にします。結論から言うと、WordPress は PHP で動いているため、PHP のバージョンが古ければ、影響を受けうる、ということです。この記事では、確認の方法と、あわせて確認したい WordPress 本体の脆弱性について、IPA の情報をもとに整理します。

WordPress と PHP の関係

WordPress は、PHP というプログラムの上で動くシステムです。そのため、2026年10月に公表された PHP の脆弱性（PHP2shell）の対象となる版を使っていれば、WordPress のサイトも、影響を受けうることになります。詳しくは、PHP2shell とは？何が問題で、何をすればいい？をご覧ください。

注意したいのは、WordPress 本体の更新では、PHP のバージョンは変わらないことです。PHP は、ホスティング環境（サーバー）側で更新します。

PHP のバージョンを確認する方法

  • WordPress の管理画面で見る：「ツール」→「サイトヘルス」→「情報」→「サーバー」の、PHP のバージョンの項目を見ます。
  • サーバー会社の管理画面で見る：多くのサーバー会社では、管理画面に、PHP のバージョン（または設定）の項目があります。
  • 制作会社やサーバー会社に聞く：いちばん確実な方法です。「PHP のバージョンを教えてください」と聞くだけで、答えてもらえます。

バージョンが分かったら、PHPバージョン診断（無料）に入力すると、更新が必要かを判定できます。

どのバージョンなら安全か

IPA によると、PHP の次のバージョンより前の版が対象で、修正版は、各系統の最新版です。

PHP の系統修正版（この版以降）
8.2 系8.2.35
8.3 系8.3.36
8.4 系8.4.27
8.5 系8.5.12

PHP 8.1 以前は、サポートが終了しており、PHP のプロジェクトからは、更新が提供されません。サーバー会社が、独自に対策していることもあるため、確認が必要です。また、PHP 8.2 のセキュリティサポートは、2026年12月31日に終了します（php.net）。

WordPress 本体の脆弱性（wp2shell）も確認する

PHP とは別に、WordPress 本体にも、2026年7月に重大な脆弱性（CVE-2026-60137 と CVE-2026-63030、通称 wp2shell）が公表され、IPA が注意喚起を出しています。IPA によると、対象と修正版は、次のとおりです。

対象のバージョン修正版
WordPress 6.9.0 〜 6.9.46.9.5
WordPress 7.0.0 〜 7.0.17.0.2
WordPress 6.8.0 〜 6.8.5（CVE-2026-60137 のみ対象）6.8.6

IPA は、直ちに更新することを推奨しています。WordPress.org は、自動更新で、強制的に更新する対応をとったとしていますが、自動更新が無効になっていたり、失敗していたりする場合があります。管理画面の「ダッシュボード」→「更新」で、いまのバージョンを確認し、修正版に上がっていなければ、手動で更新してください。

WordPress を使い続けるか、見直すか

WordPress は、多くのサイトで使われている、便利な仕組みです。ただ、更新を続ける人（または会社）がいないと、いまのように、重大な脆弱性が見つかったときに、対応が遅れます。次のような場合は、運用の見直しを検討するとよいでしょう。

  • PHP や WordPress の更新を、誰が行っているか分からない
  • 制作した会社と、連絡が取れなくなっている
  • 使っていないプラグインや、古いテーマが、たくさん残っている

Kairos では、WordPress に頼らず、お客様の業務に合わせた管理画面まで設計する制作を行っています。一方で、既存の WordPress サイトの修正・改善も、ご相談を承ります（既存サイトの修正 1万円〜）。更新や点検をお任せいただく保守プランも用意しています（ライト 月5,000円〜／税込、最低契約6か月）。ホームページ全体の「守り」は、セキュリティのセルフチェック（無料）でも確認できます。ヒアリングは無料です。蟹江町や近隣の方は、対面でも相談できます（蟹江町のホームページ制作）。
